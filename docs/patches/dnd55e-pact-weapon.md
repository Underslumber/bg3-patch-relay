# Сохранение оружия договора вне активного слота

| | |
|---|---|
| Мод | [DnD 5.5e All-in-One BEYOND](../../README.md#-затронутые-моды) |
| Версия на момент патча | 4.11.22.2 (`main` @ `81a394a4`, 09.08.2026) |
| Файлы в Patch Relay | `Mods/…/ScriptExtender/Config.json`, `Mods/…/ScriptExtender/Lua/BootstrapServer.lua` |
| Файл в чужом моде | `dnd5.5e_Remove_PactOfBlade.txt` |
| Механизм | серверный Lua-обработчик с постоянной таблицей привязок |
| Требование | BG3 Script Extender 29+ |
| Базис | пять правил `Unequipped` снимали `PACT_BLADE`, `PACT_BLADE_NECROTIC`, `PACT_BLADE_PSYCHIC`, `PACT_BLADE_RADIANT` и `PACT_BLADE_WEAPON` |

**Зачем.** В базисе перенос оружия договора из активного слота в инвентарь разрывал привязку. Обработчик запоминает `PACT_BLADE` и выбранный стихийный статус, а после `Unequipped` восстанавливает снятые исходным Story статусы. На одного владельца хранится одно оружие; при новой привязке прежние статусы снимаются. При смерти владельца или его выходе из активной группы (`CharacterLeftParty`) договор полностью снимается. При загрузке сессии дополнительно удаляются связи с отсутствующим владельцем, владельцем вне группы или отсутствующим оружием.

`PACT_BLADE` продолжает давать `Attribute(InventoryBound)`, поэтому снятое оружие остаётся недоступным для продажи. Отдельная TEST v8 загрузила обработчик и в runtime-логе подтвердила цикл `Captured → Unequipped tracked → Restored` для обычного пакта и варианта `PACT_BLADE_PSYCHIC`; игровая проверка также покрывала обычный и стихийные варианты.

Очистка по `Died`, `CharacterLeftParty` и контроль владельца при загрузке добавлены после этой проверки и требуют отдельной проверки в игре: увольнение спутника в лагерь, увольнение наёмника, сюжетное временное удаление и загрузка сохранения с владельцем вне активной группы.

**Особенность сопровождения.** При обновлении DnD 5.5e проверять исходные статусы `PACT_BLADE*` и правила `Unequipped` в `dnd5.5e_Remove_PactOfBlade.txt`. Если апстрим перестанет снимать договор при обычном снятии оружия, обработчик нужно удалить.

**История.** Проблема описана в issue #1112; исправление предложено апстриму в PR #1118.
