# Пустой тессеракт капсулы Пустоты

| | |
|---|---|
| Мод | [Ancient Mega Pack](../../README.md#затронутые-моды) |
| Версия на момент патча | 22.74.1.2 (`Version64` `803048110702985218`) |
| Файлы в Patch Relay | `Mods/…/ScriptExtender/Config.json`, `Mods/…/ScriptExtender/Lua/BootstrapServer.lua`, `CapsulePoolExpansion.lua`, `CapsulePoolBaseItems.lua` |
| Файлы в чужом моде | `ZZ_AMP_VoidCapsule_Core.txt`, `ZZ_AMP_VoidCapsule_Reroll.txt`, `ZZ_AMP_VoidCapsule_SeedReset.txt`, `TreasureTable.txt` |
| Механизм | общий аварийный обработчик пустой награды для всех типов и редкостей капсул |
| Требование | BG3 Script Extender 29+ |
| Базис | все капсулы проходят одну цепочку `SpawnReward` → `SeedReset` → `Done` → `TemplateAddTo`; имя RootTemplate награды имеет вид `AMP_Capsule_Reward_<тип>_<ступень>_<UUID>`, а соответствующий пул — `REL_<редкость>_<тип>` |

**Подтверждённый runtime-сбой.** `PROC_AMP_SeedReset_Next(..., 0)` вызывает `PROC_AMP_SeedReset_Done` сразу после появления последнего служебного контейнера, не дожидаясь окончания его асинхронной TreasureTable-генерации. В журнале Legendary Destructive `Done` сработал в `06:03:31.892`, предмет последней пустышки появился в `06:03:31.992`, а финальный контейнер начал генерироваться в `06:03:32.025`. Финальная и служебная генерации перекрылись, и финальный контейнер остался пустым.

**Отвергнуто.** Отдельный алгоритм Legendary, гонка удаления старого предмета, перестановка `PendingReward`, исчерпание `Unique`, числовой `Unique = 0` как причина и повторный вызов того же сломанного генератора.

**Текущий патч.** Поздний повторный `GenerateTreasure` проверен с загруженными статическими таблицами и фактическим уровнем 11: восемь точных категорий подряд не добавили предмет в уже созданный финальный контейнер, поэтому этот путь отключён. Общий статический патч собирает все 2420 точных stats-записей из 88 капсульных пулов и мягко переопределяет только целочисленное поле `Unique` значением `0`. Это заменяет некорректные `data "Unique" ""` Ancient Mega Pack валидным повторяемым значением до запуска SeedReset и финальной генерации. Алгоритм капсул, таблицы, веса, редкости и RootTemplate не заменяются.

**Отвергнутые общие ремонты.** Прямой RootTemplate создаёт базовую версию предмета вместо tier-stats из TreasureCategory, поэтому Legendary-капсула начинает выдавать Rare и Uncommon. Создание/обновление временной TreasureTable через `Ext.Stats.TreasureTable.Update` во время выдачи привело к воспроизводимому падению игры сразу после определения пустого финального контейнера. Эти пути не должны включаться или публиковаться.

Прямое создание RootTemplate отвергнуто: RootTemplate содержит базовую версию предмета, а нужная редкость накладывается TreasureCategory. Штатный контейнер, `DB_AMP_Reroll_ContainerInfo`, извлечение предмета, окно реролла, расход монеты и заряда не заменяются.

**Проверка.** Первичная выдача и рероллы ранее сбойной Legendary-капсулы прошли без повторного Lua-fallback; новые предметы из xFED фактически выпадали в диагностическом режиме. Штатный успешный путь подтверждается `Loot AddedTo ... decoyRowsAtAdd=0`; строк `Static fallback generate` быть не должно.

## Расширение пулов предметами других модов

`CapsulePoolExpansion.lua` после загрузки stats заново обходит фактический `LoadOrderedModules`. Для каждого модуля он сравнивает накопительные наборы `Ext.Stats.GetStatsLoadedBefore` с предыдущей границей и тем самым находит `Armor` / `Weapon`, последним владельцем которых является именно этот активный мод. Из результата исключаются Larian, Ancient Mega Pack, Patch Relay и 1429 имён базового снаряжения из `CapsulePoolBaseItems.lua`. Поэтому отключённый либо удалённый мод перестаёт участвовать, а новый активный мод подхватывается без пересборки Patch Relay.

Предыдущая попытка разницы соседних границ была смещена на один модуль: API включает в результат сам переданный модуль, поэтому схема `next - current` приписывала предметы следующего мода текущему, пропускала xFED и захватывала переопределения. Текущая схема использует `current - previous`; базовый список исключений отдельно не позволяет считать ванильные переопределения новыми предметами.

Строгие признаки — редкость, `RootTemplate`, точная `TreasureCategory I_<stats>` и слот. Каждый предмет всегда попадает в кандидаты `All` и своего слота. Тематика многозначная: любое прямое упоминание соответствующего урона, статуса, бонуса к характеристике, спасброску, навыку, атаке или классовому ресурсу в самом предмете либо связанном с ним эффекте включает его в `Arcane`, `War`, `Psionic`, `Nature`, `Primal`, `Celestial`, `Shadowfell`, `Swamp`, `Aquatic` или `Destructive`. Весов и порога нет; один предмет может входить в несколько пулов.

Каждая точная `TreasureCategory I_<stats>` добавляется в первый subtable целевого пула с весом `1`; исходные категории и параметры таблицы сохраняются, уже существующие категории не дублируются. Обновление выполняется при `StatsLoaded` либо `SessionLoaded`, но не во время выдачи награды, где динамический `TreasureTable.Update` уже приводил к падению. Нечисловой `Unique` импортируемого предмета нормализуется в `0` и синхронизируется до добавления категории; явные числовые значения, включая `Unique = 1`, сохраняются.

Рабочий смешанный режим сохраняет все штатные категории и subtables Ancient Mega Pack и добавляет к ним все найденные новые категории той же редкости. Искусственного минимума и добора из соседних редкостей нет; пул без новых кандидатов не меняется. Диагностический режим `new-only`, временно заменявший затронутые пулы только новыми предметами, удалён после подтверждения их фактической выдачи.

Отчёт `Script Extender/PatchRelay/capsule-pool-expansion-audit.log` содержит принятые и отклонённые stats, исходный мод, редкость, слот, все назначенные пулы и найденные признаки, а также число изменённых таблиц, добавленных категорий и ошибок проверки после записи.
