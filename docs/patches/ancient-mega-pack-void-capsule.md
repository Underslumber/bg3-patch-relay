# Восстановление награды из зависшей капсулы Пустоты

| | |
|---|---|
| Мод | [Ancient Mega Pack](../../README.md#затронутые-моды) |
| Версия на момент патча | 22.74.1.2 (`Version64` `803048110702985218`) |
| Файлы в Patch Relay | `Mods/…/ScriptExtender/Config.json`, `Mods/…/ScriptExtender/Lua/BootstrapServer.lua` |
| Файлы в чужом моде | `ZZ_AMP_VoidCapsule_CoinToReward.txt`, `ZZ_AMP_VoidCapsule_Core.txt`, `ZZ_AMP_VoidCapsule_SeedReset.txt` |
| Механизм | серверный Lua-предохранитель для зависшей отложенной выдачи |
| Требование | BG3 Script Extender 29+ |
| Базис | `PROC_AMP_VoidCapsule_SpawnReward` записывает `DeferredSpawn` и запускает `SeedReset`; тот создаёт 1–10 служебных тессерактов через один глобальный `DB_AMP_SeedReset_Spawning(1)`, после чего `PROC_AMP_SeedReset_Done` должен удалить отложенные записи и создать настоящий контейнер награды |

**Зачем.** В подтверждённом сохранении небесная монета исчезла, Разрушительная капсула потеряла заряд, а у владельца остался пустой `Небесный тессеракт разрушения`; нового легендарного предмета не было. Таблица `REL_Legendary_Destructive` при этом заполнена. Аналогичный плавающий сбой наблюдался и с другими капсулами, поэтому патч относится к общему маршруту выдачи, а не к одной монете или таблице.

**Подтверждённый риск в коде.** Флаг `DB_AMP_SeedReset_Spawning(1)` общий и не привязан к владельцу, шаблону награды или конкретной операции. Это делает его кандидатом на гонку событий, но конкретный момент рассинхронизации в живом Osiris-логе ещё не пойман. Независимо от причины зависания, если цепочка не доходит до `Done`, уже потраченные монета и заряд штатный код не возвращает.

Обработчик слушает `PROC_AMP_VoidCapsule_SpawnReward`. Нормальная операция синхронно удаляет свою запись `DB_AMP_VoidCapsule_DeferredSpawn`; такую выдачу патч не трогает. Если через 1,5 секунды точная запись всё ещё существует, это проверяемый признак незавершённой операции. Обработчик удаляет зависшее состояние `SeedReset` только для пары владелец+шаблон, сбрасывает общий флаг и вызывает штатный `PROC_AMP_SeedReset_Done`. Он же отслеживает контейнеры, созданные до удаления `DeferredSpawn`, и через две секунды удаляет только эти служебные экземпляры. Настоящий контейнер появляется после удаления `DeferredSpawn` и под очистку не попадает.

Патч предотвращает новые потери награды. Уже сохранённый пустой тессеракт автоматически не восстанавливается: Ancient Mega Pack очищает transient-записи `DeferredSpawn`, `TagPending` и `PendingReward` при загрузке уровня, поэтому связь с потраченной операцией в таком сейве утрачена.

**Проверка.** Статический базис сверён с установленным `Ancient Mega Pack` той же версии и API чтения/удаления Osiris DB в Script Extender. Runtime-проверка патча ещё обязательна: загрузить сохранение до расходования монеты, последовательно проверить небесную монету в Разрушительной и ещё одной капсуле, убедиться в появлении предмета, удалении служебного тессеракта и отсутствии строк `Recovered` на штатно завершившихся операциях.

**Особенность сопровождения.** После обновления Ancient Mega Pack сверять названия и арность `PROC_AMP_VoidCapsule_SpawnReward`, `PROC_AMP_SeedReset_Done`, `DB_AMP_VoidCapsule_DeferredSpawn`, `DB_AMP_SeedReset_Active` и `DB_AMP_SeedReset_Spawning`. Если апстрим сделает состояние `SeedReset` отдельным для каждой операции или уберёт ложные контейнеры, обработчик следует удалить.
