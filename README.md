# BG3 Underslumber — Patch Relay

Приватный слой патчей поверх чужих модов Baldur's Gate 3. Мод ничего не добавляет от себя: он переопределяет отдельные записи и добавляет точечные обработчики исправлений. Для статов мод обязан грузиться **последним**.

Что и зачем переопределено — в [PATCHES.md](PATCHES.md): разделы по патчируемым модам, в шапке каждого — ссылка на исходники мода, внутри подразделы по переопределённым записям. Этот реестр и есть смысл репозитория: без него через полгода непонятно, какой апдейт чужого мода что ломает.

## Устройство

```
Mods/PatchRelay_146ee64d-…/meta.lsx                     идентичность мода и зависимости
Mods/PatchRelay_146ee64d-…/ScriptExtender/Config.json   конфигурация Script Extender
Mods/PatchRelay_146ee64d-…/ScriptExtender/Lua/*.lua     серверные обработчики
Public/PatchRelay_146ee64d-…/Stats/Generated/Data/*.txt переопределения статов
scripts/build-lslib.ps1                                 сборка .pak через LSLib + установка в игру
scripts/link-bg3-dev-folders.ps1                        симлинки в Data/ игры для Toolkit (+ unlink-)
scripts/sync-parent-meta.py                             Dependencies по мете патчируемого мода
```

UUID мода — `146ee64d-4202-44ea-bd9a-87fbcc4aa36e`, каталог во всех ветках `PatchRelay_146ee64d-4202-44ea-bd9a-87fbcc4aa36e`.

## Как пишется патч

Мягкое переопределение — `new entry` плюс `using` с тем же именем: наследуется запись, загруженная раньше (чужая), и меняются только перечисленные поля.

```
new entry "BLADESONG"
type "StatusData"
data "StatusType" "BOOST"
using "BLADESONG"
data "Boosts" "…"
```

Без `using` запись создаётся с дефолтными полями и **затирает чужую целиком** — так делать только осознанно.

Переопределяется поле целиком, а не его часть: если в патче есть `Boosts`, всё содержимое `Boosts` из чужого мода замещается. Поэтому в патч копируются и те бусты, которые менять не собирались.

Обработчики Lua используются только для исправлений, которые нельзя выразить мягким переопределением статов. Для них требуется BG3 Script Extender версии 29 или новее.

## Сборка и установка

```powershell
./scripts/build-lslib.ps1              # собирает PatchRelay_146ee64d-….pak в корне репозитория
./scripts/build-lslib.ps1 -Install     # плюс кладёт его в папку модов игры
```

Имя скрипта называет тип сборки: `build-lslib.ps1` пакует через `Divine.exe` из LSLib и игры не требует; для официального Toolkit от Larian появится отдельный `build-toolkit.ps1`.

Путь к `Divine.exe` берётся из `$env:BG3_DIVINE`, иначе из соседнего репозитория `bg3-dnd55e-russian-localization/.tools/lslib`.

После установки — включить мод в менеджере и убедиться, что он стоит **ниже** всех патчируемых модов в порядке загрузки.

Версию сборки можно задать тегом: `-VersionTag v1.2.0` подставит её в `meta.lsx` пакета, не трогая репозиторий; чтобы записать и в него — добавить `-WriteMeta`.

## Разработка в Toolkit

```powershell
./scripts/link-bg3-dev-folders.ps1     # подключить
./scripts/unlink-bg3-dev-folders.ps1   # отключить
```

Скрипт заводит симлинки из репозитория в `Data\` игры, и Toolkit видит мод как свой проект — при этом правится по-прежнему репозиторий. Игра ищется через реестр Steam; нужны права на создание симлинков (режим разработчика Windows). `Editor\Mods` и `Projects` подключаются, только когда появятся в репозитории — до заведения мода в тулките их нет.

Пока мод подключён, игра берёт его из репозитория, а не из установленного `.pak` — держать обе копии сразу не нужно.

Публикация из тулкита переписывает `Mods/…/meta.lsx`: поднимает версию, проставляет размер и MD5 пакета, приводит `Dependencies` к установленному моду. Это нормальный ход вещей — файл принадлежит тулкиту.

Одно ограничение стоит помнить: **в `meta.lsx` только ASCII**. Тулкит читает его как cp1251, а пишет UTF-8, поэтому `—` в имени мода превратилось в «вЂ”» и в таком виде показалось в списке модов игры. Русский текст — в документации, не в манифесте.

## Проверка после апдейта чужого мода

1. Взять свежую версию чужого мода — из репозитория исходников, указанного в шапке его раздела в `PATCHES.md`, либо распаковав `.pak`.
2. Сверить исходную запись с колонкой «Базис» в подразделе патча.
3. Совпало — патч жив; изменилось — переписать патч и обновить подраздел; починили у себя — удалить патч и перенести подраздел в «Снятые».
4. Обновить строку зависимости: `python scripts/sync-parent-meta.py --check` покажет расхождения с `meta.lsx` чужого мода, без `--check` — применит их.
